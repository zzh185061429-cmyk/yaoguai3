# NAI Studio — NovelAI 角色立绘工作台

零依赖、无构建的本地 NovelAI 生图工具（cg-studio 的姊妹工具：cg-studio 对接 gpt-image 做场景 CG，本工具对接 NovelAI 做角色立绘）。令牌登录、快速生图、角色矩阵批量、alpha 去白边、订阅面板、Anlas 预算。

## 启动

```bash
cd tools/nai-studio
node server.mjs
# 打开浏览器访问 http://127.0.0.1:17892（端口被占用时: PORT=18000 node server.mjs）
```

或双击 `启动NAI-Studio.bat`。要求 Node 18+。服务器只绑定 127.0.0.1，不对外网开放。

## 功能总览

- **💎 订阅面板**（页头常显）：档位、Anlas 余额、会员到期、V5 用量池；5 分钟自动轮询 + 每次生成后刷新
- **🖼 通用生图**：卡片式快速出图，danbooru 标签联想（NAI 官方 suggest 接口），参考图 📁 本地上传或手填（img2img）
- **🧙 角色立绘工坊**：角色卡（人设锚点串 + 变体池×数量）→ 一键展开任务表 → 批量生成，自动按 `文件夹/角色名-变体-序号.png` 归档；seed 策略（随机/固定同脸/扫描）
- **✂ 自动去白边**：按 alpha 通道处理（见下），批量执行，产出 `xxx_cut.png`
- **✨ 提示词工坊**：不只是翻译——标签芯片编辑器（NAI `{}`/`[]` 权重语法可视化调节、增删标签实时同步）+ AI 四模式（中译英/扩写加细节/瘦身去冗余/按风格改写）+ 从最近生成/任务行/全局前缀导入 + 一键发送到卡片/锚点/前缀/收藏
- **🏷 画师串收藏库**：存好用的人设串/画师组合，一键插入全局前缀，联想列表置顶（⭐）
- **🌐 代理助手**：自动检测系统代理 + 常见梯子端口探测 + 一键应用（Node 24 NODE_USE_ENV_PROXY）
- **Anlas 预算**：批量前预估 + 执行中硬闸，超限自动停；批量结束对比真实余额变化
- **断点续跑**：manifest.json 记录进度，中断重开自动跳过已完成

## 去白边原理（为什么不会误伤白尾巴/白袍/鼻尖阴影）

NAI 生成的 PNG **自带 alpha 透明通道**。本工具的判定依据是**透明度结构**而不是颜色：

1. 低 alpha 噪点清零
2. 对实体区腐蚀 1~2px，把轮廓外的半透明窄环（白边）衰减掉
3. 对剩余半透明像素做去白色合成：`c' = (c − (1−a)·255) / a`，把混进边缘的白色从颜色里减掉
4. 实心边缘内侧与更内侧像素混色，压掉内侧白晕

白袍、白尾巴、鼻尖阴影都是 **alpha=255 的实心区域**，与"半透明窄环"结构不同——原理上不会被误删。这是它和按颜色泛洪抠图（cg-studio 旧版）的本质区别。

## 网络与代理

本工具需要本机能访问 `image.novelai.net` / `api.novelai.net` / `text.novelai.net`。

**关键事实：Node 的 fetch 不走浏览器/系统代理——挂了梯子也连不上是正常的。** 解法（按推荐顺序）：

1. **梯子开 TUN / 全局模式**：网络层接管，无需任何配置
2. **工具内「检测代理」**（设置面板 → 网络与代理）：自动读 Windows 系统代理注册表 + 探测 Clash(7890/7897/7899)/v2rayN(10808/10809)/SSR(1080) 常用端口，一键应用；原理是 Node 24+ 的 `NODE_USE_ENV_PROXY` 全局注入。**应用后需重启服务**（地址在首次请求前注入，改地址不重启不生效）
3. **梯子客户端开启「系统代理」开关**：本工具会自动跟随（注册表检测）
4. 手动：`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7890 node server.mjs`

## 真机验证清单（待你首次实测确认）

工具的核心 payload 对齐 V4.5（来源：NekoAI-JS/NyaNovel 开源源码交叉验证），以下点在 V5（2026-08-21 发布）上需一次真机确认，工具已按"可输入可兜底"设计，验证后如字段有出入只需小改：

1. **V5 模型名**：`nai-diffusion-5-full` / `nai-diffusion-5`（来自官方博客；下拉已含，失败时看日志 HTTP 状态）
2. **V5 payload 结构**：假设沿用 V4.5 字段（v4_prompt 等）——若 400 错误，抓一次网页请求对比
3. **Anlas 余额字段**：订阅响应里 Anlas 的确切字段名（当前按候选字段探测 + 原始 JSON 兜底）
4. **V5 用量池（Opus）**：剩余量/恢复时间的字段（电池式恢复：按像素+步数消耗，约一周充满）
5. **V5 透明背景**：官方说可用 prompt 开启（试 `transparent background` 标签）

Anlas 估算锚点（2026-08-23 实测）：非 Opus 标准档 V4.5 ≈ 17 / V5 ≈ 26，已写入倍率（V4.5 ×0.85、V5 ×1.3）；如与网页显示不符以网页为准。

## 目录说明

```
tools/nai-studio/
  server.mjs      # 服务器：NAI API 层、zip 解包、任务队列、拓扑排序、manifest、预算
  public/         # 前端单页（原生 JS + cutout.js 去白边算法，浏览器/Node 共享）
  data/           # 运行数据：config.json（含 NAI 令牌，已 gitignore）
  _probe/         # 自动验证脚本（已 gitignore）
```

`data/` 与 `_probe/` 均已加入仓库 `.gitignore`，**令牌不会入库**——但令牌 = 账号钥匙，也不要把 config.json 直接发给别人。

## 已知边界

- 走 zip 端点（`/ai/generate-image`），不实现 msgpack 流式——进度粒度是"每张"而非逐步
- 多角色（charPrompts）后端 payload 已支持，UI 暂未做角色编辑器（二期）
- vibe transfer / Director 工具（lineart、官方 bg-removal、upscale）后端常量已备，UI 二期
- V3 模型可用但按简化结构发送；主攻 V4.5/V5
- 去白边对"没有 alpha 的图"（jpg 等）无效——那需要 AI 抠图模型，二期
